connection_error_action

  • how to handle a connection or initialization error
  • invalid configuration settings are also treated as initialization errors since they could keep data from processing as expected
  • if changing the default value, change it in the settings array of the class file for connection errors. the database connection is made in the constructor, so updateSetting() cannot be used to change this setting until after the connection has been established.
  • valid values: 'exit', 'continue_without_database'
    • exit: completely end the program
    • continue_without_database: the program continues, but subsequent database functions will not execute. functions that modify data will do nothing and functions that return data will return empty results
  • note that there is no option to continue_with_database
  • predefined options; default = exit
connection_error_action is set to "exit". the program will end on a connection or initialization error.
$db->updateSetting('connection_error_action', 'exit'); // update a setting that does NOT exist. this is an initialization error $db->updateSetting('setting_does_NOT_exist', true); // a message will display (see error_output_html) and debugging information will optionally display (see output_error_debugging) // the program will completely end
connection_error_action is set to "continue_without_database". the program will continue after an initialization error, but database queries will be skipped.
$db->updateSetting('connection_error_action', 'continue_without_database'); // update a setting that does NOT exist. this is an initialization error $db->updateSetting('setting_does_NOT_exist', true); // the program will continue // query functions will not work. functions that return data will return empty results. // no data-modifying actions will work (INSERT, UPDATE, DELETE) // this function will not query the database and will return empty results. the result will be the same whether the query is valid or whether data exists $customer = $db->row('SELECT * FROM customers LIMIT 1;'); // $customer is null or an empty array (depending on return_null_on_error)


query_error_action

  • how to handle a query error
  • valid values: 'exit', 'continue_without_database', 'continue_with_database'
    • exit: completely end the program
    • continue_without_database: the program continues, but subsequent database functions will not execute. functions that modify data will do nothing and functions that return data will return empty results
    • continue_with_database: the program continues and subsequent database functions will continue normally
  • predefined options; default = continue_without_database
query_error_action is set to "exit". the program will end on a query error.
$db->updateSetting('query_error_action', 'exit'); // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist;'); // a message will display (see error_output_html) and debugging information will optionally display (see output_error_debugging) // the program will completely end
query_error_action is set to "continue_without_database". the program will continue after a query error, but database queries will be skipped.
$db->updateSetting('query_error_action', 'continue_without_database'); // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist;'); // $result is null or an empty array (depending on return_null_on_error) // the program will continue // query functions will not work. // functions that return data will return empty results. no data-modifying actions will work (INSERT, UPDATE, DELETE) // this function will not query the database and will return empty results. the result will be the same whether the query is valid or whether data exists $customer = $db->row('SELECT * FROM customers LIMIT 1;'); // $customer is null or an empty array (depending on return_null_on_error)
query_error_action is set to "continue_with_database". the program will continue after a query error, but database queries will process normally.
$db->updateSetting('query_error_action', 'continue_with_database'); // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist;'); // $result will be an empty value // the program will continue // query functions will not work. functions that return data will return empty results. // no data-modifying actions will work (INSERT, UPDATE, DELETE) // this function will query the database normally $customer = $db->row('SELECT * FROM customers LIMIT 1;'); // $customer will be set assuming that the query is valid and a record exists in the table


error_output_html

  • HTML that will be displayed when an error causes the program to exit
  • is only displayed when query_error_action or connection_error_action are set to "exit"
  • text; default = "<div>There was an error loading the page</div>"
// set the message $db->updateSetting('error_output_html', '<div>An Error Occurred</div>'); // update settings to end the program on query error $db->updateSetting('query_error_action', 'exit'); // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist;'); // "An Error Occurred" message will display in a div // the program will completely end


output_error_debugging

  • output debugging information to the screen when an error causes the program to exit
  • debugging information is only displayed when query_error_action or connection_error_action are set to "exit"
  • should be set to false in production environments
  • true or false (boolean); default = false
output_error_debugging is set to false. when an error causes the program to exit, debugging information will NOT be displayed
$db->updateSetting('output_error_debugging', false); // update setting to exit the program on query error $db->updateSetting('query_error_action', 'exit'); // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist;'); // no debugging information is displayed // the program will completely end
output_error_debugging is set to true. when an error causes the program to exit, debugging information will be displayed before exiting
$db->updateSetting('output_error_debugging', true); // update setting to exit the program on query error $db->updateSetting('query_error_action', 'exit'); // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist;'); // debugging information is displayed with details about the failed query // the program will completely end


return_null_on_error

  • on query error, return null
  • affects all(), row(), column(), one(), rowById(), and oneById()
  • default behavior is to return an empty, a blank string, or false depending on the function
  • allows the developer to distinguish between a valid query that returns no results and a query error
  • true or false (boolean); default = false
return_null_on_error is set to false.
$db->updateSetting('return_null_on_error', false); // valid query that will never return a result $customer = $db->row('SELECT * FROM customers WHERE false LIMIT 1;'); // $customer will be an empty array() // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist LIMIT 1;'); // $result will be an empty array()
return_null_on_error is set to true.
$db->updateSetting('return_null_on_error', true); // valid query that will never return a result $customer = $db->row('SELECT * FROM customers WHERE false LIMIT 1;'); // $customers will be an empty array() // query a table that does not exist. this will generate a query error $result = $db->row('SELECT * FROM table_does_not_exist LIMIT 1;'); // $result will be null


id_field_name

  • the unique identifier column in tables
  • used by all "ById" functions to find a record by identifier
  • will usually not need to be changed since most databases use "id" as the identifier field name
  • text; default = "id"
id_field_name is set to uuid. this tells the database that "uuid" is the unique identifier for tables
$db->updateSetting('id_field_name', 'uuid'); // retrieve for a row in a table by id (if it exists) $customer = $db->rowById('customers', 'ab06f63e-8fe7-11ec-a514-5405db7aad56'); // the SQL that will process will be something like "SELECT * FROM customers where uuid=:uuid limit 1;", ":uuid" will be bound to "ab06f63e-8fe7-11ec-a514-5405db7aad56" using PDO // $customer will be set if the record exists


max_records_per_insert_query

  • maximum number of records to include in each SQL query generated by insertMultiple() and insertMultipleFieldsValues()
  • higher values can be more efficient because fewer queries are needed, but use more system resources and increase the chance of exceeding system limitations
  • the default (100) is a very conservative value; values in the tens of thousands will likely work fine for typical data
  • integer; default = 100
max_records_per_insert_query is set to 1000.
$db->updateSetting('max_records_per_insert_query', 1000); // $customers is an array of data for 10,000 customers with the following format: // $customers = array( // array('first_name'=>'Joe', last_name=>'Jones', username=>"joe_jones"), // array('first_name'=>'Sally', last_name=>'Williams', username=>"s_williams"), // ... [more records with the same formatting] ... // ); // single function call to insert all $isSuccess = $db->insertMultiple('customers', $customers); // behind the scenes, the function will generate SQL to insert all data. Based on the setting, 1,000 will be // inserted per query. So to insert all 10,000 customers, 10 queries will be sent to the database // if all records are successfully inserted, $isSuccess will ge true


delete_and_update_require_where

  • DELETE and UPDATE queries require a WHERE clause
  • used to avoid accidentally deleting or updating all rows in a table
  • just a simple check that the string "WHERE" is in the query, could still allow a DELETE or UPDATE in certain rare cases: "DELETE from places_where_ive_been;" or "UPDATE books SET title='Where the Wild Things Are';"
  • to affect all rows in a table, set WHERE clause to "true", ex: "DELETE FROM places_where_ive_been WHERE true;"
  • true or false (boolean); default = true
delete_and_update_require_where is set to false.
$db->updateSetting('delete_and_update_require_where', false); // DELETE query with no where clause $isSuccess = $db->query('DELETE FROM customers;'); // all rows in the table will be deleted // $isSuccess is true
delete_and_update_require_where is set to true.
$db->updateSetting('delete_and_update_require_where', true); // DELETE query with no where clause $customer = $db->query('DELETE FROM customers;'); // an error will be generated. the query will not be processed (no rows deleted) // $isSuccess is false // DELETE query with where clause that will delete all rows $customer = $db->query('DELETE FROM customers WHERE true;'); // all rows in the table will be deleted // $isSuccess is true


max_rows_for_table_display

  • the maximum number of rows to display as an HTML table when outputting an array using the display() function
  • if an array has more rows, the array is displayed using PHP's var_dump() function
  • integer; default = 1000
max_rows_for_table_display is set to 99.
$db->updateSetting('max_rows_for_table_display', 99); // assume that there are more than 100 records in the $customers table // retrieve up to 99 customer records // since there are more than 100 records in the table, the $customers array will have 99 rows $customers = $db->all('select * from customers limit 99;'); // 99 rows will display in a table $db->display($customers); // retrieve up to 100 customer records // since there more than 100 records in the table, the $customers array will have 100 rows $customers = $db->all('select * from customers limit 100;'); // trying to display 100 rows, but max_rows_for_table_display is set to 99 rows // the function will instead use PHP's var_dump() function to display the array $db->display($customers);


save_query_run_time

  • track processing start and end times (to calculate duration later)
  • useful for testing, but adds some overhead, so normally set to false in production unless the information is needed for another purpose, such as analysis
  • true or false (boolean); default = false
save_query_run_time is set to false. query start and end times will NOT be tracked.
$db->updateSetting('save_query_run_time', false); // run a query $customer = $db->row('SELECT * from customers limit 1;'); // display information on the most recent query $db->displayLastQueryInfo('settingDoesNotExist', true); // output information will NOT include "duration"
save_query_run_time is set to true. query start and end times will be tracked.
$db->updateSetting('save_query_run_time', true); // run a query $customer = $db->row('SELECT * from customers limit 1;'); // display information on the most recent query $db->displayLastQueryInfo('settingDoesNotExist', true); // output information will include "duration"
